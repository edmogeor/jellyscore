# JellyScore

JellyScore is a Jellyfin 12 plugin that finds likely theme music on YouTube for movies and TV series, saves it where Jellyfin recognizes it, and lets administrators manage plugin-downloaded themes. A missed theme is preferable to a wrong match or a change to someone's own files.

## Terms and scope

- **Theme**: audio Jellyfin recognizes in an item's folder, including `theme.*` and audio in `theme-music/`.
- **Managed theme**: a `theme.mp3` downloaded by this plugin whose item, folder, path, and file hash still match its ownership record. An existing, manually added, or externally modified file is not managed.
- **Recording**: the track identity used to distinguish a replacement from another upload of the same music. A YouTube video ID identifies a source upload, not necessarily a different recording.
- Only physical movies in dedicated folders and physical series roots inside writable libraries are eligible. Automatic processing uses selected libraries; explicit administrator adds can use any library. Episodes, seasons, extras, virtual items, and movies in mixed or shared folders are not.
- The control surface is a Jellyfin administrator-only page and API. There is no manual candidate-review queue.

## Discovery and selection

- Automatic processing of new items and scans after completed Jellyfin library scans are separate settings, both enabled by default. An unset library selection means all libraries; an explicitly empty selection means none. Installation does not itself backfill existing items.
- Administrators can set a minimum match strength from 0 to 100. The default is 50, including existing settings without a saved value. Match strength is the candidate's bounded ranking score (0 to 100), not a probability. Apply the minimum after hard eligibility checks and before category preference, including refresh and failed-source fallback. A changed minimum affects future searches, not files already installed.
- New item events enter the same processing queue as administrator actions, with Activity progress, cancellation, outcomes, and retries. Wait for metadata and the physical folder before processing, preserving automatic library selection and deletion suppression; issue retries are explicit administrator adds. Events arriving during a full scan wait until it stops. A completed Jellyfin library refresh can independently queue a full scan when that setting is enabled. Administrators can start or cancel a full scan of selected libraries regardless of either automatic setting and see counts, the current item with its processing stage, tool preparation when needed, recent rejection reasons, progress, and an approximate time remaining seeded from the last completed scan (or a first-run default) and adjusted as items finish.
- Administrators can optionally provide a public HTTPS TV theme URL template with a numeric `{tvdbId}` in its path. For series with a saved TVDB ID, try it before YouTube only when adding a new managed theme. Reject redirects and local addresses; bound download time and size, require valid audio duration, and apply the same conversion and file-ownership checks. A failed or unusable URL falls back to YouTube. Movies and series without a TVDB ID use YouTube. Refresh skips the URL source to seek another recording.
- Search uses the Jellyfin display title, original title when present, production year, and theme or soundtrack terms. Titles broaden retrieval; a search query alone never proves a candidate belongs to that work. Search results are shortlisted before full video metadata is fetched. A full-album tracklist can supply a search hint, but the album itself is not a theme candidate.
- A movie's TMDb collection name, when present in Jellyfin metadata, identifies its franchise even if no Jellyfin collection exists. Administrators may opt to prefer a clearly identified shared franchise theme over a film-specific theme for future movie searches; if none qualifies, use the normal film-specific search. Franchise matching does not require the film title or release year, but rejects tracks identified as belonging only to a known individual installment. Independently of that setting, process physical Jellyfin collections selected in the Collections library when their name and member's TMDb collection name agree. Show the Collections library selection only while Jellyfin has collection items. Store their themes in the collection folder and manage them with the same ownership, refresh, deletion, and suppression rules as movie themes. Never overwrite an existing theme or replace an already managed film theme simply because the preference changed.
- Reject mismatched works, years, adaptations, sequels, regional versions, covers, remixes, fan edits, clearly labeled live performances, tutorials, trailers, reviews, compilations, and full albums. A work title containing "Live" is not by itself a live-performance label. Film-versus-TV soundtrack labels in the title or identified album indicate the wrong edition; incidental mentions of "movie" or "TV" in free-form descriptions do not. A series title attached to another named theme does not establish that the music belongs to the series; an explicit description linking that recording as the TV show's theme can. A named track can qualify when its title, soundtrack album, or description ties it to the correct work and edition. For short movie or series titles without release-year evidence, consult Jellyfin's enabled TMDb film and TV metadata searches only when relaxing the year requirement would change the selected recording. If it confirms the item's ID and year with no competing same-title film or show, a yearless upload still needs the work in its title or identified album; incomplete, failed, or ambiguous lookups retain the year requirement. An upload older than the year before the work's production year cannot be its theme; a newer upload does not prove a match or establish the work's release year.
- For example, do not use a UK Office opening for *The Office (US)* or a 1984 or Part Two track for *Dune* (2021). A recording titled "Hedwig's Theme" can still qualify for *Harry Potter and the Sorcerer's Stone* when its soundtrack metadata links it to that film.
- Require a known duration of 10 seconds to 8 minutes for both series and movies. First reject ineligible works, editions, dates, and formats; ranking cannot rescue a contradiction. Score the remaining candidates with additive evidence, not a probability:

  | Evidence | Points |
  | --- | ---: |
  | Full work title in video title, or partial title words | +30, or up to +16 |
  | Matching work year in title/album, or linked description/track metadata | +30, or +20 |
  | Matching film/TV edition label in title or identified album | +20 |
  | Main theme/title, theme, opening/intro | +20, +15, +12 (opening and theme can combine) |
  | Identified track on matching soundtrack album, with named artist | +40, plus +15 |
  | Soundtrack/OST/score label, official claim, music channel | +10 maximum, +5, +3 |
  | Duration 30 seconds to 6 minutes, short opening, 6 to 8 minutes, other short recording | +10, +10, +5, -10 |
  | Multi-season opening/title-card collection, other collection-style title | -30, or -20 |

  For series, prefer the highest-scoring explicit theme, opening, or intro over other soundtrack tracks; an otherwise equal theme scores slightly above a bare intro. Multi-season collections can remain fallback candidates but rank below comparable standalone themes. For movies, prefer main themes, then closing credits, then soundtrack tracks. Accept the highest-scoring eligible recording meeting the administrator's minimum in the preferred category; when recordings tie, choose the first search result. Equivalent uploads of one recording remain interchangeable sources.
- Incomplete searches, unavailable tools, and failed downloads are failures, not proof that no match exists. A complete search without an eligible recording reports a reason. Retry transient failures with bounds; a failed download may try one other eligible source without permanently blacklisting the failed upload.

## Audio and file ownership

- The plugin packages a yt-dlp release identifier and its checksums, not executables. On first use it downloads only the server's platform-specific binary, verifies its checksum, and caches it in Jellyfin's plugin configuration directory; a failed or unverifiable download appears in the admin page with a retry action. For YouTube's JavaScript challenges it uses a supported Deno or Node.js installed on the server, or downloads a checksum-verified Deno release on supported platforms, without bundling a runtime executable. Administrators may optionally save YouTube cookies in plugin settings; pass them to yt-dlp through a restricted temporary file, then remove that file after each invocation. Pace yt-dlp requests across new items, scans, and admin actions; when YouTube rate limits the server, pause further requests rather than retrying immediately. It uses Jellyfin's FFmpeg installation. It downloads only the selected audio, measures its integrated loudness and true peak, then converts it to `theme.mp3` with a single fixed gain targeting the administrator's chosen loudness (FFmpeg's supported -70 to -5 LUFS range, default -30) without exceeding -3 dBTP and one-second fades at the start and end. The setting applies to future downloads and refreshes, not existing files. Peak headroom takes priority over the loudness target; never compress or dynamically normalize the recording. It never processes manually added themes.
- Place a movie's theme beside its movie file in a dedicated folder, or in a series' physical root. Check Jellyfin's recognized themes and physical theme files before downloading and again before committing. Do not overwrite a non-plugin theme, even if a stale record claims ownership.
- Convert to a temporary file in the destination folder, validate it, then move it into place. A failed conversion or replacement must leave the existing theme untouched. Refresh Jellyfin's item metadata after a successful write or deletion.
- Persist managed item IDs, canonical paths, library IDs, source identifiers and URLs, recording identities, hashes, scores, and dates in plugin configuration data, not in media folders. Serialize work per item. Before replacing or deleting a file, confirm that its location and hash still match the record. Treat a changed or moved file as user-owned and leave it alone. When listing themes, remove stale records for changed or deleted items without deleting their files; defer reconciliation when a media folder is temporarily unavailable.

## Admin actions

- Manage Downloads uses a height-capped, keyboard-focusable scroll panel with sticky column headers and pagination outside the panel. Preserve its inner scroll position during row updates and reset it for a new search or page. Row action menus float above scroll clipping. The add-theme modal puts result cards in a separate inset scroll panel sized to the viewport.

- While a scan runs, disable add, refresh, source edits, per-item deletion, bulk deletion, and issue retries, and reject those mutations in the admin API. Keep playback, searching, pagination, issue navigation, and scan cancellation available.
- Disable full scans while administrator adds, refreshes, or source edits are queued or processing. Check the shared queue before accepting a scan in the API and again when the scheduled scan starts. Completed and failed queue entries do not block scans.

- Manage Downloads lists only installed managed themes. Queued and unsuccessful adds appear in Activity, with no placeholder cards or Remove from list action. An unsuccessful add remains eligible for Add theme after processing stops, independently of retained issue history. Add-theme search results use native radio groups for keyboard selection and a persistent polite live region to announce result counts, empty results, and errors. Closing the add modal returns focus to the Add theme action. Individual shared-queue actions confirm acceptance with an item-naming toast. The first manual add prepares the same checksum-verified yt-dlp and JavaScript runtime as a scan, without needing a prior scan.

- **Add theme** is a global Manage Downloads action with a modal to live-search eligible movies, series, and collections without themes across all libraries, then automatically find a theme or provide a YouTube video URL. Search feedback appears in the results area. Confirmation queues server-side processing alongside refresh requests and closes the modal immediately; queued work, stages, and unsuccessful outcomes appear in Activity. Add the item to Manage Downloads only after a managed theme is installed. Queued work survives page navigation, but the in-memory queue does not survive server restarts. Explicit adds can restore deleted themes without a full scan, process only the chosen item, and never replace an existing theme. Managed themes remain manageable independently of automatic library selection. Manual URLs use the same validation, duration, conversion, and ownership checks as source editing.

- Remember the selected tab and preview volume/mute for the browser session, without storing settings drafts in browser storage. Background reloads preserve edited settings; warn before leaving with unsaved changes. Managed-theme refreshes update the displayed date while retaining table order using a separate original-added timestamp, as well as the active search, page, scroll position, and row focus. Older records use their existing date as the initial ordering timestamp. Show filtered-result counts and an in-field search clear button; return focus to the row menu after action dialogs close.
- **Play theme** opens an audio-preview dialog with a source link and a locally packaged Video.js audio player and locale packs. Its controls use the same resolved language as the page, without downloading translations from a CDN. Show loading and buffering in the player's own play control while keeping the timeline and volume controls visible. Use Jellyfin's indexed theme matching the managed file path and its authenticated original-file API; stop playback and release the audio when the dialog closes or the administrator leaves the page.
- The admin page controls automatic processing and selected libraries, shows activity progress and a last-run summary with a bounded, scrollable list of timestamped skipped items and failures, and lists searchable, paginated managed downloads with source links and status. Administrator-visible rejection reasons and action errors are translated in the page from stable codes; diagnostic text in logs and stored outcomes remains unchanged. Failed activity issues offer administrators a copy action for the exact diagnostic message logged for bug reports, without displaying that text in the issue list. Only administrators can read the management API or change settings, start scans, refresh, or delete.
- **Activity** uses one current-activity and Last run presentation for full library scans and administrator queued jobs, with identical progress, current-item stages, approximate remaining time, outcome counts, cancellation, and timestamped issues. Do not show upcoming items or origin/action labels differentiating scans, adds, refreshes, source edits, and queued batches. A queue run starts when an idle queue accepts a job and ends when no waiting or active work remains; jobs added during a run increase its total. Progress counts completed items, and remains indeterminate only while the total is unknown. Cancel stops current processing safely and discards waiting work, preserving completed results without counting cancellation as failure. Show Cancelling until active work stops. Retain only the latest completed activity for the server session, including duration and bounded issue history, across navigation; a completed scan or queue run replaces it. Active work is expanded above collapsed Last run; its completion summary stays expanded. Issue history is independent of downloads search, pagination, and retries; preserve its original reasons, timestamps, counts, and diagnostics after recovery. Live updates preserve issue-list scroll and focus and announce lifecycle changes and failures rather than every progress tick. Downloads, add results, issues, and scrollable action menus share themed scrollbar styling. Disabled scan actions show an inline explanation while the queue runs.
- Download cards are quiet by default: omit past success/skip outcomes and queued-job error paragraphs, show compact Queued/Working indicators for active work, and retain current file-availability warnings. Show an accessible issue icon only for an unresolved issue still present in current Activity or Last run, preferring the newest issue for the item's ID. Use a neutral information icon for skipped outcomes and a warning icon for failures. Hide obsolete warnings after a successful replacement or newer result, and remove their links when the corresponding run leaves retained history. Clicking an icon expands its run and issues section, scrolls to the exact issue, and focuses it. Issue cards have only a thin accent outline on focus, without extra background, shadow, or animation. Immediate request, deletion, and playback errors use contextual item-naming toasts; form validation remains inline.
- Eligible Activity issues offer a Retry icon beside Copy error when diagnostics are available; there is no YouTube-source action in Activity. Retry queues only that item and repeats its original add, refresh, chosen-source edit, or saved-source redownload. Redownload retries capture the currently saved loudness setting. Scan issues retry as explicit administrator adds; unsupported items, lost ownership, and unavailable managed themes do not offer retry. Reject retries for expired or resolved issues, during full scans or cancellation, and while the same item is already queued. A successful retry clears the associated warning without rewriting the original issue's diagnostic history. YouTube source selection remains in Add theme and the managed-theme row menu. Only current/last-run issues retain retry descriptors; do not introduce a separate error history.
- The Activity card's primary line shows the current item and its translated stage. While preparing yt-dlp and the JavaScript runtime, show the tool-preparation message alone, without an item-name prefix; restore the item and stage when preparation finishes. Show Preparing before there is a current item; after stopping, show Completed, Cancelled, or the stopped reason without retaining an active-looking last item. Put the completed/total count and ETA on a separate secondary line without the word "processed"; the count stays at 0 of X until the first item finishes and matches the progress bar. Last run and its native disclosure chevron sit inside the same bordered card as its expanded results, without a nested card border.
- **Add**, **Refresh**, and **Edit YouTube source** share one server-side processing queue across administrators and items, with processing stages and outcomes in the downloads table. Requests return once queued and continue independently of the browser. Each refresh excludes the current source video and recording, then seeks a different eligible recording. Skip known excluded video IDs before full metadata checks without letting them occupy shortlist slots; other uploads of the excluded recording remain ineligible at selection. If none qualifies or the replacement fails, the existing file stays in place. Source and recording exclusions persist across restarts and scans; transient download failures do not create permanent exclusions.
- **Edit YouTube source** prefills the current source only when it is a YouTube video URL; themes from the configured TV URL source start with an empty field. Accept only YouTube video links, never arbitrary custom URLs or playlist-only links, and canonicalize them before invoking yt-dlp. Confirmation queues the chosen video alongside refresh requests. Administrator selection bypasses automatic matching and prior-source exclusions, including when reprocessing the current video, but still requires the supported duration, audio conversion, and all ownership checks. A failed replacement leaves the existing theme intact.
- **Delete** removes only an unchanged managed file, then suppresses automatic re-download for that item. **Delete all** applies the same ownership checks to every managed download, across all search results and pages, and reports files it could not safely delete. A subsequent full scan clears deletion suppression, including a scan queued after a Jellyfin library refresh. Neither action removes another theme file or a `theme-music/` directory.
- **Redownload all themes** is a confirmed Manage Downloads action across every managed item, library, search result, and page. Queue the entire batch atomically in the shared processing queue, including batches larger than the single-request queue capacity, and report the accepted count. Disable and reject it during a full scan or other queued processing. Redownload fresh audio from each saved YouTube source or original TV theme URL, then apply the loudness setting captured when the batch was accepted, with the normal duration, conversion, peak-headroom, fade, and temporary-file validation. Do not search for another recording, fall back to another source, use a changed TV URL template, re-encode the installed MP3, or add source/recording exclusions. Preserve saved recording identity, source, score, evidence, and original-added order; update the date and hash only after successful replacement. Retain ownership and hash checks before processing and committing, and keep existing themes when a source is missing, unavailable, invalid, or conversion fails. Externally modified and user-added themes are left untouched. Saved TV URLs retain the same public HTTPS, redirect, address, time, and size restrictions as their initial downloads. Progress, cancellation, failures, and last-run results use Activity. Saving audio settings alone does not modify existing files; redownloading explicitly applies them.
